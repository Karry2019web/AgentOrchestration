# Release Process

This project uses SLSA provenance attestation to ensure the integrity and
traceability of all release artifacts.

## How Releases Work

1. A maintainer pushes a tag matching `v*.*.*` (e.g., `v2.5.0`).
2. The [Release workflow](.github/workflows/release.yml) triggers automatically.
3. The workflow:
   - Runs tests and builds distribution packages
   - Generates a **provenance attestation** using the
     [SLSA Generic Generator](https://github.com/slsa-framework/slsa-github-generator)
   - Creates a GitHub Release with both packages and the provenance file

## Verifying Provenance

After downloading a release artifact, verify its provenance using the
GitHub CLI:

```bash
gh attestation verify <artifact-file> \
  --repo orchestration-agent/AgentOrchestration
```

Or using the Makefile target:

```bash
make verify-provenance
```

The attestation is an in-toto statement (JSON) signed by GitHub's OIDC
identity. It includes:

- **Source repository**: orchestration-agent/AgentOrchestration
- **Source commit**: the exact commit SHA from which the artifact was built
- **Workflow**: the Release workflow run that produced the artifact
- **Artifact digest**: SHA-256 hash of the artifact file

## What the Provenance Attestation Contains

The provenance file (`provenance.intoto.jsonl`) uses the
[SLSA v1.0](https://slsa.dev/spec/v1.0/) predicate and contains:

- `subject`: the artifact filename and its SHA-256 digest
- `predicate.buildDefinition`: the workflow that produced the artifact, including
  the source repository, commit SHA, and build parameters
- `predicate.runDetails`: the GitHub Actions run metadata (run ID, trigger event,
  builder ID)

## Acceptance Criteria (Issue #2276)

- [x] Each release artifact has a matching provenance attestation
- [x] The attestation includes source repository, commit, workflow, and artifact digest
- [x] Verification instructions are included in release documentation

## Security Notes

- The provenance is generated by the trusted release workflow using
  OIDC-based identity (not manually uploaded)
- The attestation can be verified offline using the
  [slsa-verifier](https://github.com/slsa-framework/slsa-verifier) tool
- Only tags pushed by maintainers with write access can trigger provenance
  generation
